What We Built

Product Mission

Sales-Connections turns passive network knowledge into actionable sales leads. Contributors log curated Connection Idea records about real people in their professional networks; the system uses AI to draft outreach talking points; sales reps prioritize and execute against those records.

Architecture

Three-tier web app on AWS — synchronous, simple, scalable to 10,000 records per organization.

System Context

Three tiers, four synchronous integration surfaces.

No message queues. No event buses. No async DB drivers. Synchronous-only by design.

Data Model

Six tables, three enum types, append-only audit at the database privilege layer.

erDiagram organizations ||--o{ users : "has" organizations ||--o{ records : "owns" organizations ||--o{ tags : "owns" users ||--o{ records : "submitted by" records ||--o{ record_tags : "tagged via" tags ||--o{ record_tags : "applied via" users ||--o{ audit_events : "actor" records ||--o{ audit_events : "target" organizations { uuid id PK text name } users { uuid id PK uuid org_id FK text email user_role role } records { uuid id PK uuid org_id FK uuid owner_user_id FK text linkedin_url text normalized_linkedin_url involvement_type involvement outreach_status outreach_status timestamptz deleted_at } tags { uuid id PK uuid org_id FK text name } record_tags { uuid record_id PK uuid tag_id PK } audit_events { uuid id PK uuid actor_user_id FK uuid target_record_id FK audit_event_type event_type timestamptz event_timestamp }

Every entity carries org_id from day one — multi-tenant data model, single-org runtime in MVP.

Request Lifecycle

Atomic state-change + audit emission in a single transaction.

sequenceDiagram autonumber participant B as Browser participant API as Flask API participant MW as Middleware Stack participant H as Handler participant S as Service participant DB as PostgreSQL B->>API: HTTPS request (cookie session JWT) API->>MW: correlation, auth, RBAC MW->>H: pass to handler H->>H: pydantic validation H->>S: call service rect rgb(220, 240, 220) S->>DB: BEGIN S->>DB: INSERT record S->>DB: INSERT audit_event S->>DB: COMMIT end S-->>H: persisted entity H-->>B: response with correlation_id

Green block is atomic — both succeed or both roll back. Sub-100 ms audit emission.

Why

Five architectural decisions that define the platform.

Decision Highlights

Reference: docs/decision-log.md for the complete log.

Synchronous-only No message queues, no event buses, no async DB drivers. Synchronous-only ensures audit-emission atomicity within a single transaction.
Append-only audit Application database role has INSERT only on audit_events. Even SQL injection cannot mutate audit history.
Multi-tenant data model Every entity carries org_id from day one. Single-org runtime today; multi-org-ready forever.
Soft delete by default deleted_at flag preserves audit referenceability. Hard delete is Admin-only and explicitly audited.
Provider-replaceable AI Anthropic SDK isolated behind Langchain. Swap providers without touching feature handlers.
Observability built in Structured logs, distributed tracing, /metrics endpoint, /healthz and /readyz, CloudWatch dashboard. The application is not complete until it is observable.

Risk and Mitigation

Known unknowns documented; mitigations engineered in or scheduled for follow-up.

Risk Register

Each risk is mitigated, documented, or scheduled for follow-up.

AI dependency on Anthropic Single-provider AI dependency for the F-002 note generation feature.
Mitigated 5-second timeout watchdog; AI failure is non-blocking on form submission; provider-replaceable via Langchain abstraction.
Single-region AWS deployment Regional availability dependency on the chosen AWS region.
Mitigated Multi-AZ RDS for high availability within region; multi-region active-active is post-MVP per the scope boundary.
Single-org runtime in MVP No org-onboarding flow ships with MVP; only one organization is served at runtime.
Mitigated Data model is multi-tenant from day one; org-onboarding UI is deferred to post-MVP without rework.
No inbound API rate limiting No per-user or per-IP throttle in MVP.
Mitigated TLS at the ALB; authentication required for every state-changing endpoint; rate limiting is documented as a post-MVP next step.

All risks tracked in docs/decision-log.md and docs/operations.md.
